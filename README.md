# PokeBattleBar

같은 네트워크(LAN)에 있는 동료와 **PokeTokenBar 도감 포켓몬으로 1:1 배틀**하는 macOS 앱.

PokeTokenBar 를 수정하지 않는 **별도 컴패니언 앱**이다.
`companion-state.json` 을 **읽기 전용**으로만 참조하므로, PokeTokenBar 가 자동 업데이트돼도 깨지지 않는다.

## 동료에게 배포하기

```sh
./scripts/release.sh 1.1.0
```

5개 검증 스위트를 **전부 통과해야만** 산출물이 나온다. 실패하면 배포가 중단된다.

**`build.noindex/PokeBattleBar-1.1.0-Install.command` 이 파일 하나만** 보내면 된다 (약 1.6MB).
앱이 파일 안에 들어 있어서 다운로드도 압축 해제도 필요 없다. 실행하면:

1. macOS 버전과 PokeTokenBar 설치 여부를 확인한다 (포켓몬 몇 마리인지도 알려준다)
2. 실행 중인 기존 앱을 종료한다
3. 앱을 꺼내고 격리 속성을 제거한다
4. `/Applications` 에 설치한다 (필요하면 sudo)
5. 실행하고, 로컬 네트워크 권한 안내를 보여준다

업데이트도 같은 파일을 새로 만들어 보내면 된다 — 기존 버전을 알아서 갈아끼운다
(`설치됨: v1.1.0 → 설치할 버전: v1.2.0` 처럼 보여준다).

받는 쪽 요구사항:
- macOS 14 이상 (Apple Silicon / 인텔 둘 다 — 유니버설 바이너리)
- **PokeTokenBar 설치 + 포켓몬 최소 1마리** (`brew install --cask poke-token-bar`)
  포켓몬 정보는 각자 맥의 상태 파일에만 있으므로 전원이 두 앱을 다 깔아야 한다.

### 실행 방법 — `bash` 를 앞에 붙인다

```sh
bash ~/Downloads/PokeBattleBar-1.1.0-Install.command
```

터미널에 `bash ` 를 치고(공백 포함) 파일을 창으로 끌어다 놓고 엔터.

**그냥 더블클릭하거나 `bash` 없이 실행하면 실패한다.** 파일 전송 과정에서
실행 권한(+x)이 벗겨지기 때문에 `permission denied` 가 나고, 권한이 남아 있어도
Gatekeeper 가 "확인되지 않은 개발자" 경고를 띄운다.
`bash` 로 넘기면 실행 권한과 무관하게 동작하고 Gatekeeper 도 거치지 않는다.

### Gatekeeper

Apple 유료 개발자 서명이 없어서, 전송된 파일에는 격리(quarantine) 속성이 붙는다.
설치 파일이 앱의 격리 속성은 알아서 떼주지만, **설치 파일 자체의 첫 실행**은
macOS 가 경고를 띄운다. 터미널로 실행하면(방법 2) Gatekeeper 를 아예 거치지 않는다.

마찰을 완전히 없애려면 Apple Developer 계정(연 $99)으로 서명 + 공증(notarize) 해야 한다.

`build.noindex/poke-battle-bar.rb` 에 Homebrew cask 초안도 함께 생성된다 —
tap 저장소를 쓸 생각이 있으면 URL 만 채우면 된다.

### 소스에서 직접 빌드 (격리 문제 없음)

로컬 빌드한 앱에는 격리 속성이 붙지 않는다. Command Line Tools 만 있으면 된다 (Xcode 전체 불필요).

```sh
xcode-select --install
git clone <이 저장소> && cd PokeBattleBar
NATIVE=1 ./scripts/bundle.sh     # 내 맥 아키텍처만 — 더 빠르다
open build.noindex/PokeBattleBar.app
```

### 첫 실행

**"로컬 네트워크 접근 허용"을 반드시 눌러야** 방 검색이 된다. 거부하면 조용히 실패한다.
되돌리려면 시스템 설정 → 개인정보 보호 및 보안 → 로컬 네트워크.

## 규칙

| 항목 | 내용 |
|---|---|
| 팀 구성 | 도감 완성본 + 진행중 동반 포켓몬. **방 상한까지 보유한 만큼** |
| 비대칭 | 허용된다. 2마리 가진 사람은 6마리 상대에게 불리하다 (의도된 것) |
| 방 설정 | 최대 사용 포켓몬 수(1~6), 레벨(50/100), 상태이상·랭크변화·급소 on/off |
| 기술 | 배울 수 있는 기술 중 **랜덤 4개**를 개체별로 한 번 뽑아 고정. 배틀 중 매 턴 골라서 쓴다 |
| 교체 | 없다. 쓰러지면 그때 다음 포켓몬을 고른다 |
| 스탯 | 종족값 + 성격 보정. 개체값 31 / 노력치 0 전원 동일 |
| 누적 토큰 | **반영하지 않는다.** 승패를 가르는 건 포켓몬 종류·타입·성격·뽑힌 기술뿐 |
| 특수 변신 | 메가진화 / 다이맥스 / 거다이맥스 / Z기술. **각각 배틀당 1회**, 해당 도구 필요 |
| 게임 모드 | 랜덤 기술 · 자유의지 · 변신 자동 선언 · 토게피 손가락흔들기 (토글) |
| 지닌 도구 | 메가스톤·Z크리스탈·다이맥스밴드·다이버섯 + 배틀 도구(구애·생명의구슬 등) |
| 특성 | PokeAPI 의 실제 특성. 구조화한 것만 계산에 반영되고, 나머지는 표시만 |
| 날씨 · 필드 | 쾌청·비·모래바람·눈 + 4종 필드. 날씨 기술과 특성으로 발동 |
| G-Max 전용기 | 32종. 거다이맥스 중 타입이 맞으면 전용기로 변환 |

진행중(진화 미완성) 동반 포켓몬도 팀에 넣을 수 있지만 현재 단계의 종족값으로 싸운다 — 약하다.

## 게임 모드

방 설정에서 켠다. **앞의 세 개는 자유롭게 조합**할 수 있고, 토게피 모드는 단독으로 동작한다.

| 모드 | 내용 |
|---|---|
| **랜덤 기술** | 저장된 기술 대신 배틀마다 배울 수 있는 기술에서 4개를 새로 뽑는다. 저장본은 그대로 남는다 |
| **자유의지** | 플레이어가 고르지 않고 포켓몬이 4개 중 무작위로 쓴다. 선봉·교체도 자동 |
| **변신 자동 선언** | 도구를 끼웠다면 메가진화·다이맥스·거다이맥스·Z기술이 무작위 시점(턴당 35%)에 발동한다 |
| **토게피 손가락흔들기 1:1** | 아래 참조 |

### 토게피 손가락흔들기 1:1

양쪽 모두 **토게피 1마리**로 싸운다. 토게피를 도감에 가지고 있는지는 상관없다.

- 기술은 **손가락흔들기 하나**, PP 는 **최대치**(PP Up 3회 = 10 → 16)
- **생명의구슬** 장착 (데미지 1.3배, 최대 HP 10% 반동)
- 로스터·도구·특성 설정은 전부 무시된다

**손가락흔들기는 PokeAPI 가 "무작위 기술" 이라는 효과를 구조화해 주지 않아 직접 구현했다.**
배틀 중에는 네트워크를 쓸 수 없으므로, 이 엔진이 실제로 재현할 수 있는 기술 207종을
미리 받아 풀로 둔다 (공격기 148 + 변화기 59). Z기술·맥스기술·손가락흔들기 자신은 제외된다.

## 버전 호환성

배틀하려면 **양쪽 프로토콜 버전이 같아야 한다.** 다르면 방 목록에 "버전 불일치" 로
표시되고 자동 매칭에서 제외되며 참가가 막힌다 — 누가 구버전인지도 알려준다.

메시지 구조를 바꿀 때는 `Net/Wire.swift` 의 `PokeBattleProtocol.version` 을 올린다.
Swift 의 합성 Codable 은 프로퍼티 기본값을 쓰지 않으므로, **신규 필드가 하나만 늘어도**
구버전이 보낸 JSON 은 디코딩이 실패한다. 버전 확인은 본문 해석보다 **먼저** 해야 한다
(순서가 반대면 디코딩 실패가 먼저 터져 원인을 알 수 없다).

## 특수 변신 — 메가진화 / 다이맥스 / 거다이맥스 / Z기술

**플레이어당 각 종류를 배틀 한 번에 한 번씩만** 쓸 수 있다.
6마리를 데려갔다면 한 마리는 메가진화, 다른 한 마리는 다이맥스, 또 한 마리는 Z기술 —
여섯 마리가 모두 다이맥스할 수는 없다.

**다이맥스와 거다이맥스는 같은 슬롯을 쓴다** (원작에서 같은 자원이다 —
거다이맥스는 자격 있는 종이 다이맥스할 때의 특별한 형태). 둘 중 하나만 쓸 수 있다.

기술을 고르는 화면에서 선언한다 (원작처럼 기술 선택과 동시에). 선언하면 기술 버튼의
상성 배지와 실질 위력이 **변환 후 기준으로 즉시 바뀐다.**

| | 자격 | 필요한 도구 | 효과 |
|---|---|---|---|
| **메가진화** | 메가 폼이 있는 종 | 해당 메가스톤 | 타입·종족값 교체 (HP 유지). 배틀 끝까지 |
| **다이맥스** | 제한 없음 | 다이맥스 밴드 | 최대 HP ×1.5, 3턴, 기술이 맥스 기술로 |
| **거다이맥스** | 거다이맥스 폼이 있는 종 | 다이버섯 | 다이맥스 + 전용기 |

두 도구는 **역할이 겹치지 않는다** — 다이맥스 밴드로는 거다이맥스를, 다이버섯으로는
일반 다이맥스를 할 수 없다. (원작에서는 둘 다 지닌 도구가 아니다. 밴드는 트레이너의
열쇠 아이템이고 다이버섯은 거다이맥스 인자를 여는 요리 재료다 —
도구 슬롯 하나로 자격을 관리하기 위한 각색이다.)
| **Z기술** | 해당 타입 공격기 보유 | 그 타입 Z크리스탈 | 그 턴 공격 한 번이 Z기술로. 필중 |

리자몽처럼 메가 폼이 둘인 경우(X/Y) 끼운 스톤이 어느 쪽인지 결정한다.

**님의 현재 로스터**: 쥬레곤(87)과 꿀꺽몬(317)은 메가·거다이맥스 폼이 없다.
다이맥스와 Z기술은 도구만 끼우면 쓸 수 있다.

위력은 PokeAPI 가 주지 않아서(`power=null`) **원작 변환표**를 직접 넣었다:
Z기술은 원래 위력 40→100, 90→175, 상한 200. 맥스기술은 40→90 (격투·독은 낮은 표로 40→70).

## 지닌 도구

PokeAPI 에서 실제 도구 데이터(한글명·효과 텍스트) 를 받아 배틀 효과로 매핑한다.
로비에서 개체마다 하나씩 끼운다. 선택은 `loadouts.json` 에 저장된다.

| 도구 | 효과 |
|---|---|
| 구애머리띠 / 구애안경 / 구애스카프 | 공격·특공·스피드 1.5배, 처음 쓴 기술로 고정 |
| 생명의구슬 | 데미지 1.3배, 최대 HP 10% 반동 |
| 기합의띠 | 풀피에서 받는 일격을 1 HP 로 버틴다 (1회) |
| 먹다남은음식 | 턴마다 최대 HP 1/16 회복 |
| 달인의띠 | 효과가 굉장한 기술 1.2배 |
| 힘의머리띠 / 박식안경 | 물리 / 특수 1.1배 |
| 진화의휘석 | 미진화 포켓몬의 방어·특방 1.5배 |
| 돌격조끼 | 특방 1.5배, 변화기 사용 불가 |
| 화염구슬 / 맹독구슬 | 턴 종료 시 자신에게 화상 / 맹독 |
| 선제공격손톱 | 3/16 확률로 선공 (원작 확률) |
| 플레이트 17종 | 해당 타입 기술 1.2배 |
| 메가스톤 / Z크리스탈 / 다이맥스밴드 / 다이버섯 | 변신 자격 |

메가스톤은 자기 종의 것만, 다이버섯은 거다이맥스 폼이 있는 종에게만 목록에 나온다.

## 특성

PokeAPI 의 373개 특성을 전부 받아 **표시**하고, 종족별 실제 특성 슬롯(숨겨진 특성 포함)
중에서 고를 수 있다. 다만 PokeAPI 는 효과를 산문으로만 주므로,
아래로 **구조화한 것만 실제 계산에 반영된다.** 나머지는 목록에 "표시만" 으로 나온다.

맹화·급류·신록·벌레의야망(궁지 강화), 위협, 부유, 옹골참, 두꺼운지방, 내열,
하드록·필터·프리즘아머, 면역·수의베일·불면·의기양양·유연·마그마의무장·마이페이스(상태 면역),
테크니션, 클리어바디·하얀연기·메탈프로텍트, 노가드, 우격다짐, 색안경, 적응력, 스나이퍼,
순수한힘·요가파워, 이상한비늘, 근성, 매직가드, 돌머리, 이판사판, 배짱, 천진,
하늘의은총, 색가루.

## 구현된 전투 요소## 구현된 전투 요소

원작 데미지 계산식, 18타입 상성표, 자기 타입 일치(STAB), 급소(1.5배), 명중/회피 랭크,
PP, 스피드 선공, 우선도, 난수 폭(85~100%), 다단히트, 흡수/반동, 회복기,
상태이상(마비·화상·독·맹독·잠듦·얼음·혼란)과 타입 면역, 능력치 랭크 ±6.

고정 데미지 기술도 지원한다: 나이트헤드·지구던지기(레벨만큼), 용의분노(40), 소닉붐(20),
목숨걸기(내 HP만큼). 자폭 기술(대폭발·자폭·메멘토·목숨걸기)은 쓴 쪽이 실제로 쓰러진다.

기술 버튼에는 **지금 상대에게 몇 배로 들어가는지**가 표시된다 — 배율 배지(×4/×2/×½/×¼/무효),
자기 타입 일치를 반영한 실질 위력, 효과 굉장/별로 판정. 메가진화로 타입이 바뀌면 즉시 갱신된다.

### 날씨 · 필드

쾌청 / 비 / 모래바람 / 싸라기눈과 4종 필드. 날씨 기술로 걸거나 특성(가뭄·잔비·모래날림·
눈퍼뜨리기)으로 자동 발동한다. 불꽃·물 데미지 배율, 모래바람 지속 피해,
날씨 의존 특성(엽록소·쓱쓱·태양의힘·아이스바디·모래숨기 등)이 모두 작동한다.

**PokeAPI 는 날씨 기술을 `whole-field-effect` 라고만 알려주고 어떤 날씨인지는 주지 않는다.**
그래서 기술 이름 → 날씨 표를 직접 넣었다.

### 거다이맥스 전용기 (G-Max)

**PokeAPI 에 G-Max 기술은 하나도 없다** (기술 937개 중 0개, 직접 조회는 404).
그래서 32종의 종 → 전용기 표와 효과를 직접 작성했다.

거다이맥스 중에 **기술 타입이 전용기 타입과 같으면** 전용기로 변환된다 (원작과 동일).
32종 중 25종의 추가 효과가 실제로 작동한다:

- 지속 피해 6종 (다이맥스채찍·파이어·포·버스트·센티퍼노·샌드) — 4턴간 최대 HP 1/6
- 상태이상 8종 (다이맥스썬더→마비, 스모그→독, 인섹트→랜덤, 스노즈→잠듦 등)
- 능력치 4종 (다이맥스버블→상대 스피드 -2, 다이맥스태클→급소율 상승 등)
- 회복·기타 7종 (다이맥스피날레·스위트·이팅·디플리션·드럼솔로 등)

나머지 7종(다이맥스고스트·윈드·그래비티·스톤즈·스틸·멜트·일격)은 스텔스록·묶기·중력처럼
**교체가 있어야 의미가 있는 효과**다. 이 게임은 교체가 없으므로 재현 대상이 아니다.

### 접촉 판정

**PokeAPI 는 기술의 접촉 플래그를 주지 않는다.** 접촉·펀치·물기·소리·가루 기술 목록을
직접 표로 넣었고, 이걸로 정전기·불꽃몸·까칠한피부·철가시·철주먹·옹골찬턱·방음이 작동한다.

**미구현**: 지배기, 발버둥. 이 효과만 가진 기술(트집·원더룸 등)은
"아무 일도 일어나지 않았다"로 처리된다. 기술 뽑기가 공격기를 최소 2개 보장하므로 배틀은 항상 진행된다.
거다이맥스의 종족별 전용 G-Max 기술(예: 무한다이빔)은 넣지 않았다 — 타입별 맥스 기술로만 변환된다.

### 이 테스트들이 잡아낸 실제 버그

각 항목은 코드를 읽어서는 발견되지 않았고, 실제로 굴려봐야 드러났다.

| 버그 | 원인 |
|---|---|
| 대폭발을 써도 자기 HP가 안 줄었다 | PokeAPI 가 자폭을 구조화해서 주지 않는다 — `effect_entries` 텍스트("User faints.")에만 있고 `meta.category` 는 일반 공격기와 동일한 `damage` |
| 맹독이 일반 독으로 걸렸다 | PokeAPI 에 "맹독" ailment 이 없다 — `toxic` 도 `meta.ailment` 가 `"poison"` 으로 온다. 누적 증가가 사라졌다 |
| 고른 포켓몬이 아니라 맨 왼쪽이 나왔다 | 선택 개수가 정원과 정확히 같지 않으면 선택을 버렸고, 방 참가 시 선택을 덮어썼고, 선봉 화면이 실제로 보낸 팀이 아닌 재계산 결과를 보여줘 인덱스가 어긋났다 |
| 거다이맥스가 끝나도 HP 상한이 안 줄었다 | `revertGmax()` 의 `guard isGmax` 가 자기 자신을 막았다 — 호출부가 턴수를 0 으로 깎은 뒤 부른다 |
| 정원 초과 접속 거절이 전달되지 않았다 | `send()` 직후 `cancel()` 해서 소켓 플러시 전에 끊겼다 |
| 조사가 "스피드이" 로 나왔다 | 받침 유무에 따른 은/는·이/가 처리가 없었다 |
| 맹독이 누적되지 않았다 | PokeAPI 에 "맹독" ailment 이 없어 `toxic` 도 `poison` 으로 온다 |
| 와이어 포맷이 비결정적이었다 | `[Stat: Int]` 이 JSON 객체가 아니라 순서가 매번 다른 배열로 인코딩됐다 (`CodingKeyRepresentable` 로 해결) |

첫 실행은 PokeAPI 에서 데이터를 받으므로 느리다. 이후는 전부 캐시에서 읽는다.

## 알려진 한계

- **부정 방지가 없다.** `companion-state.json` 은 평문이고, 게스트는 자기 팀을 스스로 신고해서 보낸다.
  상태 파일을 고쳐 전설 포켓몬 6마리를 주장할 수 있다. 사내 LAN 전제라 막지 않았다.
- 배틀 계산은 **호스트(방 만든 쪽)** 가 전담한다. 호스트가 앱을 닫으면 배틀이 끝난다.
- 한 방에 1:1 만 들어간다. 두 번째 접속은 거절된다.
- UI 는 자동 검증되지 않는다 (엔진·네트워크만 테스트 범위).
